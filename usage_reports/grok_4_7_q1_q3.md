## 字段怎么加总

这一份 `usage.json` 里，四个已结束回合逐项相加后等于会话合计，并且每个回合都满足：

```text
totalTokens = inputTokens + outputTokens
```

因此这里的 `inputTokens` 是**整段提示**，已经包含缓存命中。`cachedReadTokens` 是其中的缓存读取，不是额外再加的一截。

```text
未缓存输入 = inputTokens - cachedReadTokens - cacheCreationTokens
```

本会话 `cacheCreationTokens` 全是 0。

`reasoningTokens` 单独列出，并且小于 `outputTokens`。它**没有**再加进 `totalTokens`，否则合计会对不上。把它看成输出里的推理部分，可见输出大约是 `outputTokens - reasoningTokens`。这一点是从加法关系反推的，账本本身没有写“reasoning ⊂ output”这句说明。

`costUsdTicks / 1e10` = 美元。文档约定：10^10 ticks = 1 USD。

比例定义：

| 名称 | 算法 |
|---|---|
| 缓存占输入 | `cachedReadTokens / inputTokens` |
| 未缓存占输入 | `未缓存输入 / inputTokens` |
| 输出占合计 | `outputTokens / totalTokens` |
| 推理占输出 | `reasoningTokens / outputTokens` |

Headless 模式打印的 `usage.input_tokens` 语义不同：那里的 `input_tokens` 只计未缓存，`total_tokens` 才把 cache read 加回去。不要和这里的 `inputTokens` 直接对比。
