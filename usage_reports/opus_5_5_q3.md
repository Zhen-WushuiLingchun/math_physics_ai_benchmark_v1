## 4. 解读与注意事项

1. **为什么缓存读取占约 98%**：每次请求都要把此前整个对话（包括代码、工具输出和思考）作为上下文重新读入。这部分几乎全部命中提示缓存，按“缓存读取”计入。上下文越长、请求次数越多，它增长越快，所以缓存读取远大于实际新写入的内容。
2. **输出中约 71% 是思考 token**：`output_tokens` 包含扩展思考；`output_tokens_details.thinking_tokens` 给出其中的思考部分。可见输出（代码、报告文本、工具调用参数）约 95,963。
3. **不计 token 的部分**：后台 Python 数值计算（时域演化、频域扫描、共振求根等，共数十分钟 CPU）不消耗 token；只有工具返回给模型的输出文本才会作为后续请求的输入被计入。
4. **可能漏计一次请求**：第 ① 段最后一次有记录的请求在 02:55:28，用户中断在 02:59:13。中间约 4 分钟很可能有一次正在进行的请求，被中断后没有写入 usage，所以第 ① 段的输出可能偏少（量级为一次请求）。
5. **不是计费金额**：缓存写入、缓存读取、普通输入、输出的单价各不相同，本报告只统计 token 数，不做费用换算。会话上下文中显示的 `total_tokens left` 是上下文预算计数，不是计费用量。
6. **第 ③ 段不完整**：这是本次统计提问本身，写完这份文件之后还会有少量请求，未计入。
