## 比例口径

- **总 token** = 输入 token + 输出 token。
- **缓存输入**已经包含在输入 token 中，不能再次加到总 token 上。
- **推理 token**已经包含在输出 token 中，不能再次加到总 token 上；这一点也可由每条后台记录的 `total_tokens = input_tokens + output_tokens` 验证。
- **缓存命中率** = 缓存输入 / 输入。
- **输出占总量** = 输出 / 总 token。
- **输出/输入** = 输出 / 输入。这个比例一并给出，避免“输出比例”口径不明确。

如果按总 token 的构成来看，01–03 合计中：缓存输入占 **95.4838%**，非缓存输入占 **3.8327%**，输出占 **0.6835%**。

## 为什么数字远大于可见答案长度

这里统计的是模型请求的实际累计 token。每次分析、工具调用和续写都会再次携带上下文；同一段上下文即使命中缓存，仍会出现在 `input_tokens` 和 `cached_input_tokens` 中。因此，累计输入可达到数千万 token，而绝大部分是缓存输入，并不等于产生了数千万 token 的新文本。
