## 为什么总量超过两百万

这是 **29 次模型响应的累计输入与输出**，不是独立文本量，也不是某一次请求的上下文长度。模型多次继续工作时，之前的上下文会再次作为输入，其中很大部分被记为缓存输入。因此不能把 268.28 万 token 理解为生成了这么长的一篇解答。

例如最后一次响应的输入为 142,814 tokens，而整段任务累计输入为 2,648,478 tokens；两者统计的是不同对象。

## 可信范围

这些数值是本地日志已上报、可复算且互相一致的 token 用量。它们不等同于官方账单；尤其首次执行存在中断，日志无法证明中断时是否还有未回传 `usage` 的消耗。若有未上报请求，本报告无法补齐。

本报告不估算金额，也不将 token 比例转换为订阅额度扣减比例。浏览、Python、XeLaTeX 等工具若有独立计费，不能从这份模型 token 日志推出。

## 复算代码

以下代码只读取日志，按固定轮次筛选，因此以后继续向同一任务发送消息也不会改变这里统计的范围。

```python
from pathlib import Path
from collections import Counter
import json

（含本机路径的行已省略）
turns = {
    "[会话标识已省略]",
    "[会话标识已省略]",
}
total, seen = Counter(), set()
last = None
for line in log.open(encoding="utf-8"):
    event = json.loads(line)
    p = event.get("payload", {})
    if event["type"] != "token_usage_record" or p.get("turn_id") not in turns:
        continue
    if p["response_id"] in seen:
        continue
    seen.add(p["response_id"])
    total.update(p["usage"])
    last = p
assert dict(total) == last["thread_token_usage"]
assert total["total_tokens"] == total["input_tokens"] + total["output_tokens"]
print("records:", len(seen))
print(json.dumps(dict(total), indent=2))
print("cached / input:", total["cached_input_tokens"] / total["input_tokens"])
print("output / total:", total["output_tokens"] / total["total_tokens"])
```
